# Выпуск каждой заказанной версии

Заказанная версия не считается готовой только после локальной сборки. Если
пользователь поручил её выпуск, завершайте работу тегом, GitHub Release,
установочным ZIP и проверкой публичного обновления. Непроверенные WIP-сборки
не публикуются под видом готового выпуска.

1. Одна версия должна совпадать в `VERSION`, `bl_info`, AssemblyInfo и пакете.
2. Проверить чистую логику, затронутые сценарии Blender 4.2/5.2, исходные файлы,
   установку и откат. В отчёте отличать тесты SDK от настоящего запуска Revit.
3. Собрать шесть worker-вариантов; не пересобирать frozen loader ABI 1.
4. Собрать канонический `agr_revit_bridge-X.Y.Z.zip`, проверить manifest/SHA256
   и установку в изолированном профиле без записи Preferences.
5. Обновить README, руководство, release notes и проверенные ограничения.
6. Сохранить проверенный Git-коммит и неизменяемый тег `vX.Y.Z`, отправить их
   в репозиторий XIV-gate/revit-blender-bridge и создать Release с ZIP в Assets.
7. Ранний доступ публиковать с `prerelease=true`, не меняя Latest стабильной
   версии. Перевод в стабильный канал выполняется по принятому решению продукта.
8. Проверить анонимное получение списка, скачивание публичного ZIP и SHA256
   через тот же обновитель, которым пользуются друзья. Проверить, что Latest
   стабильной версии сохранился. Сообщить ссылку и способ обновления пользователю.

Временные профили, модели, ссылки на местные диски и результаты тестов не
коммитить. Сборки и тесты хранить только в разрешённой рабочей области проекта.
