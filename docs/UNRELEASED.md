# Не выпущено — экспорт диагностических логов

Разработано в исходниках после 0.4.4. ZIP аддона не собирался, релиз не публиковался.

В основной панели добавлена одна кнопка **«Экспорт логов»**. Выберите путь ZIP.
Она работает и во время обработки, если интерфейс Blender отвечает. Существующий
архив не перезаписывается: выберите новое имя.

Архив содержит:

- `summary.txt`: версии, состояние, длительность этапов, доступная/общая RAM,
  память Blender/Revit/конвертера и доступные сведения VRAM.
- `diagnostics.json`: настройки, числа элементов, предупреждения, временная
  шкала с UTC и местным часовым поясом, замеры памяти на переходах между этапами.
- Разрешённые журналы выбранного задания: worker, конвертация, ответы, статусы,
  диагностика ошибок, история времени и краткая статистика выгрузки.

Паузы после READY/DONE не относятся ко времени обработки. Времена наблюдает
клиент Blender: короткие стадии Revit между опросами могут объединяться.
Экспорт во время выполнения показывает, сколько уже длится текущая стадия.
После перезапуска доступен сохранённый снимок истории из папки задания; его
времена не продлеваются до текущего момента. Пик RAM — пик рабочего набора
процесса за его жизнь, а не непрерывный замер выбранного этапа.

RAM читается через Windows API. Общая, занятая и свободная VRAM читается через
`nvidia-smi`, если установленный драйвер NVIDIA предоставляет эти данные.
Для остальных драйверов/недоступных счётчиков значение явно неизвестно; нулём
оно не подменяется. Сведения VRAM снимаются только при экспорте архива,
с ограничением ожидания драйвера 3 секунды. Они не являются историческим пиком.

RVT, `.blend`, геометрия, USD, текстуры, каталог и файл команды с токеном не
включаются. Из разрешённых текстов удаляется известный токен задания.
Журналы могут содержать пути, названия и ID элементов: отправляйте их лично.
Архив ограничен по объёму; для больших логов сохраняется конец файла,
усечения и пропуски перечислены в `diagnostics.json`.

Проверка: обычные Python-тесты; настоящий оператор экспорта и чтение RAM/VRAM
в изолированных Blender 5.2.3 и 4.2.14, включая экспорт без остановки задания.
Регрессии контроллера, дельта-импорта, ошибок и дерева категорий проверены в 5.2.3.
Исходная причина медленной/неудачной выгрузки у друга ещё не установлена:
для этого нужен его диагностический архив после установки будущей сборки.
